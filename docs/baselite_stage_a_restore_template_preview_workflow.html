本文档说明当前仓库中 Stage A 的完整数据流、字段定义、执行命令、质量检查和验收结果。 Stage A 的目标是生成 restore-only 模板预览产物，用于进入 Stage B 训练前的模板审计和长度预算。

1. Stage A 的定位

Stage A 不是训练阶段，而是一个可复现的数据模板预览阶段。它把已经划分好的 data/baselite_smiles_v1/train.jsonl、valid.jsonl 和 test.jsonl 转换为 restore-only 训练样本的审计形态，并记录完整 tokenizer 长度与 round-trip 结果。

当前 Stage A 明确不接入 text_view_2、graph tensor、fragment vocab、 fragment labels，也不做 SMILES 扰动。text_view_1 固定为 identity view。
项目 Stage A 当前选择 原因
任务 L_restore 数据模板预览 先验证 restore 输入、target、token ids、mask 和长度预算。
文本视图 text_view_1 = canonical_smiles 避免把扰动策略和模板正确性混在一起。
target canonical_text_target + <|endoftext|> target 单独监督 restore head，不拼入 decoder trunk 输入。
tokenizer Qwen2Tokenizer，EOS 为 <|endoftext|> 对应 Qwen2.5-7B Base 行为，不使用 Instruct 的 <|im_end|>。

2. 输入、脚本与输出

输入文件

  • data/baselite_smiles_v1/train.jsonl
  • data/baselite_smiles_v1/valid.jsonl
  • data/baselite_smiles_v1/test.jsonl

每行必须包含 record_id、canonical_smiles、canonical_hash、graph_hash 和 split。

实现脚本

  • scripts/build_baselite_restore_template_preview.py
  • 默认 tokenizer: models/qwen2.5-7b-tokenizer/
  • 默认输出目录: data/baselite_smiles_v1/

输出文件

文件 用途
data/baselite_smiles_v1/training_template_preview.jsonl 合并的 preview 数据，每行带 split 字段，顺序为 train → valid → test。
data/baselite_smiles_v1/training_template_stats.json 机器可读统计，包括 tokenizer 信息、长度分布、质量检查和输出路径。
data/baselite_smiles_v1/training_template_report.md 人工可读 Markdown 报告，记录 Stage A 口径、模板、长度和质量检查结果。
training_template_preview.jsonl 是一个合并文件，不是只包含 train。valid 和 test 位于文件后段，并通过 split 字段区分。

3. 完整处理流程

1. 读取 split 数据 按 train、valid、test 顺序读取 JSONL。
2. 校验输入字段 检查 record_id、canonical_smiles、hash 和 split 一致性。
3. 构造 restore 文本 生成 input_text_view1 和 target_text。
4. Qwen tokenizer 分别 tokenize input 和 target，生成 ids 与 mask。
5. 统计与验收 检查 round-trip、长度上限、mask，并写出三类产物。

3.1 输入字段校验

每条输入记录必须满足：

  • record_id 非空，用于追踪原始样本。
  • canonical_smiles 非空，是 restore 的 identity view 和 canonical target 来源。
  • canonical_hash 非空，用于 canonical identity 审计。
  • graph_hash 非空，用于后续 graph identity 防泄漏和 Stage C 对接。
  • split 必须与当前读取的 split 文件一致。

3.2 restore-only 文本构造

text_view_1 = canonical_smiles
canonical_text_target = canonical_smiles

input_text_view1 =
  "<polymer_view_smiles>\n"
  + text_view_1
  + "\n</polymer_view_smiles>\n"

target_text = canonical_text_target + tokenizer.eos_token

这里的关键约束是：target_text 不拼入 input_text_view1。 训练阶段 decoder trunk 只能看到 view 输入；restore target 只作为 restore_labels 监督 restore head。

3.3 token ids 与 mask

input_ids_view1 = tokenizer.encode(input_text_view1, add_special_tokens=False)
attention_mask_view1 = [1] * len(input_ids_view1)

restore_labels = tokenizer.encode(target_text, add_special_tokens=False)
restore_label_mask = [True] * len(restore_labels)

当前 Stage A 不 padding、不截断，只记录原始长度。由于每条记录都是单样本预览，mask 全部为有效位。 真正 batch padding 会在 Stage B dataloader 或 collator 中处理。

4. Preview JSONL 字段说明

字段 类型 说明
record_id, split, canonical_hash, graph_hash string 从原始 split JSONL 继承，用于追踪、审计和后续 join。
canonical_smiles string 当前样本的 canonical repeat-unit SMILES。
text_view_1_strategy string 固定为 identity。
text_view_1 string restore 输入视图，当前等于 canonical_smiles。
canonical_text_target string restore 的 canonical 目标文本，不含 EOS。
input_text_view1 string 带 <polymer_view_smiles> 标签的 decoder trunk 输入文本。
target_text string canonical_text_target + <|endoftext|>。
input_ids_view1, restore_labels list[int] 分别是 input view 和 target text 的 Qwen token ids。
attention_mask_view1, restore_label_mask list[int] / list[bool] 当前全有效；后续 batch padding 时再扩展 padding mask。
view1_token_length, restore_label_length int 用于长度预算和 overflow 检查。

当前 preview 记录中不应出现 text_view_2 字段。

6. 质量检查规则

检查项 规则 当前结果
view round-trip decode(input_ids_view1) == input_text_view1 0 failures
restore round-trip decode(restore_labels) == target_text 0 failures
view length overflow view1_token_length <= 512 0 overflows
restore length overflow restore_label_length <= 512 0 overflows
mask consistency mask 长度等于 token ids 长度，且当前全部为有效位 0 failures

脚本会在上述任一 count 非 0 时以非 0 状态退出，避免生成“看似成功但质量检查失败”的 Stage A 产物。

8. 与 Stage B 的关系

Stage A 只证明模板和 tokenizer 路径可用，并给出长度预算。Stage B 的 text-only restore smoke test 可以直接复用相同字段，也可以在 dataloader 中在线生成完全等价的字段。无论哪种方式，都应保持：

  • input_text_view1 只包含 view，不包含 target。
  • restore_labels 只监督 restore head。
  • 第一轮 restore smoke test 仍使用 identity view，先不做扰动。
  • 如果后续加入 random SMILES、direction flip 或 mask，应作为 Stage B 之后的增强实验，不回写当前 Stage A 审计口径。
