Interpretation

Stage C full 在 final valid/test canonical、robustness valid/test canonical、token accuracy 与 RDKit validity 上均高于本地 Stage B full；restore loss 也更低。由于 Stage C 使用 30 epoch 且加入 graph/align 分支，这个结果说明当前 Stage C full 产物更强，但不能单独作为架构 ablation 归因。

Caveats

  • Stage B full 为 20 epoch，Stage C full 为 30 epoch。
  • 同 epoch 比较目前只覆盖 valid checkpoint；test/robustness 的同 epoch 严格横比需要补跑 Stage C epoch 20 checkpoint 的对应评测。
  • Stage C 的 total loss 不和 Stage B loss 直接比较；所有 loss 横比使用 restore_loss 口径。
  • Stage C retrieval / align 指标只用于分析多任务训练效果，不能和 Stage B restore-only 直接横比。
